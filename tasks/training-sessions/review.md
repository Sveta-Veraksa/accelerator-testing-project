### Should-fix

**S-1. Защиту от повторной отправки можно обойти через Cancel или «New session» во время запроса (AC-CREATE-5).**
`src/features/training-sessions/CreateSessionForm.tsx:18`, `:107`; `src/features/training-sessions/TrainingSessionsWorkspace.tsx:48`, `:80`

- Флаг `inFlightRef` живёт внутри экземпляра формы.
- Пока запрос выполняется, кнопка Cancel и переключатель «New session» остаются активными. Любой из них размонтирует форму, но сам запрос не отменяет.

Сценарий отказа:
1. Пользователь отправляет валидную форму, запрос `POST` ещё идёт.
2. Нажимает Cancel или «New session», затем снова открывает форму. Монтируется новый экземпляр с `inFlightRef = false`.
3. Отправляет форму ещё раз, уходит второй `POST`, пока первый не завершён. Это прямо нарушает AC-CREATE-5: «while a create request is pending, further submit attempts … send no additional request».
4. Когда первый запрос успешно завершается, `handleCreate` вызывает `setIsCreateOpen(false)` (строка 48). Это закрывает уже вторую форму вместе с введёнными значениями, а в список попадают обе сессии.

Ещё один вариант: нажать Cancel и ничего не открывать. Пользователь считает, что отменил создание, но сессия всё равно появится в списке.

Основание: AC-CREATE-5 и решение G-1 в плане (guard на ref + state). Это не личное предпочтение.

Минимальное исправление: пока идёт запрос, делать Cancel и переключатель недоступными. Либо держать признак «запрос в процессе» в `TrainingSessionsWorkspace`: проверять его в `handleCreate` и не размонтировать форму, пока он установлен.

### Nice-to-have

**N-1. Старое сообщение об ошибке создания остаётся при новой неудачной валидации.**
`CreateSessionForm.tsx:34-41`

Если создание завершилось ошибкой, а потом пользователь отправил невалидную форму, ранняя проверка возвращает управление до `setHasSubmitError(false)`. На экране одновременно видны сообщения валидации и «The session could not be created…», хотя запрос не отправлялся.

Это расхождение в UX, а не нарушение AC (AC-CREATE-9 выполняется).

**N-2. Теряется фокус клавиатуры, и успех создания не объявляется.**
`TrainingSessionsWorkspace.tsx:48`, `:87`

- После успешного создания или нажатия Cancel форма размонтируется вместе с кнопкой, на которой был фокус. Фокус уходит на `body`.
- Скринридер никак не узнаёт, что сессия добавлена.

Опора: правило из web-interface-guidelines «Async updates … need aria-live». Отсутствие toast — осознанное решение G-4, поэтому это не нарушение, а рекомендация.

**N-3. Если worker не стартовал, приложение не рендерится.**
`src/main.tsx:14`

У `enableMocking().then(...)` нет `catch`. Если `worker.start()` отклонится (Service Worker недоступен, нет `public/mockServiceWorker.js`, небезопасный origin), dev-страница останется пустой, а промис будет отклонён без обработки. Затрагивает только dev. Это совпадает с примером из документации MSW, поэтому личное предпочтение.

**N-4. `onUnhandledRequest: 'error'` в тестах ловит незамоканные запросы только косвенно.**
`src/test/setup.ts:6`

В MSW 2.15 (проверено по `node_modules/msw/lib/core/sharedOptions.d.ts`) режим `'error'` пишет ошибку в лог и обрывает запрос сетевой ошибкой. Сам тест он не роняет.

План утверждает, что такой запрос «fails the test». На деле тест упадёт только потому, что UI перейдёт в состояние ошибки, и `findByRole('list')` отвалится по таймауту с невнятным сообщением. Явную проверку можно добавить через `server.events.on('request:unhandled', …)`.

**N-5. Длина заголовка считается в UTF-16 code units.**
`validateNewSession.ts:28`

Например, «😀😀» даёт длину 4 и проходит минимум в 3 символа. Требования не уточняют, как считать «символы» для таких случаев, поэтому это пограничный случай, а не дефект.

**N-6. Ссылка `aria-controls` указывает на отсутствующий элемент, пока форма закрыта.**
`TrainingSessionsWorkspace.tsx:79`

Пока форма свёрнута, элемента с id `createFormId` нет в DOM. Шаблон распространённый и почти безвредный, это личное предпочтение.

**N-7. Предупреждение lint на `public/mockServiceWorker.js`.**

Coder сообщил 1 warning. Значит, утверждение плана «It is not linted» неточно. Исправление (добавить файл в ignores) затрагивает `eslint.config.js`, который план не разрешает менять. Решать разработчику.

## Отклонение msw 2.15.0 вместо 3.0.2

Сделано корректно и последовательно.

- **Причина подтверждается.** Peer-зависимость `msw` у `@vitest/mocker@5.0.3` объявлена как `^2.4.9` с `optional: true`. Но если пакет установлен, npm проверяет его версию, так что msw 3 вызвал бы ERESOLVE.
- **API соответствует версии 2.x.**
  - `onUnhandledRequest: 'bypass'` в `src/mocks/browser.ts:15` и `'error'` в `src/test/setup.ts:6` — это правильное имя опции для 2.15.
  - `{ once }` в `sessionsListError` (`src/mocks/handlers.ts:52`) поддерживается.
  - `setupWorker` берётся из `msw/browser`, `setupServer` — из `msw/node`.
  - `worker.start()` дожидается завершения до рендера (R-6).
- **Сгенерированные файлы ожидаемы.**
  - `public/mockServiceWorker.js` содержит `PACKAGE_VERSION = '2.15.0'`, что совпадает с установленным пакетом.
  - В `package.json` есть `msw.workerDirectory: ["public"]`.
  - `package-lock.json`: добавлено 111 пакетов, все с пометкой `dev`. Версии существующих пакетов не менялись, ничего не удалено. Строки с `-` в diff — это только перестановка блоков.

## Соответствие плану и AC (кратко)

- **Граница запросов (AC-MOCK-1).**
  - `fetch` вызывается только в `sessionsApi.ts`, URL строится абсолютным (R-3).
  - Тело ответа проверяется в рантайме без `any` и `as`.
  - Сообщения сервера в UI не попадают (AC-LIST-4).
  - UI не импортирует ничего из `src/mocks/**`.
- **Состояния (AC-LIST-3).** Состояние — discriminated union, поэтому loading, error и список взаимоисключающие. Retry сначала выставляет `loading`, потом увеличивает `reloadToken`.
- **Эффекты.** `AbortController` с отменой в cleanup. Отменённый запрос не переводит UI в ошибку (R-5). Зависимости эффекта корректны.
- **Фильтр.** Вычисляется при рендере и не хранится в отдельном state (правило Derived State). Ровно два варианта, у пустого результата отдельный текст (AC-FILTER-5).
- **Валидация.** Заголовок проверяется после `trim`, длина 3–80 включительно. Дата парсится как локальное время, условие `<= nowMs` даёт отказ. Сообщения связаны с полями через `aria-describedby` и `aria-live`. Фокус переходит на первое невалидное поле. Пока форма невалидна, запрос не отправляется.
- **Повторная отправка.** Внутри одного экземпляра формы защита (ref + disabled + «Creating…») работает. Пробел описан в S-1.
- **Безопасность.** Нет `dangerouslySetInnerHTML`, все данные рендерятся экранированными JSX-строками, mock-код подключается только в dev через `import.meta.env.DEV`.
- **CSS.** Есть `:focus-visible`, нет `outline: none`, нет `transition: all`. Есть `overflow-wrap` и `min-width: 0` для длинных заголовков и тёмная тема для цветов статусов.
